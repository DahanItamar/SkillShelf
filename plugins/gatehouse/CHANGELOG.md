## 0.1.0 - 2026-11-22
- First version. A read-only auditor for a skill, plugin or marketplace folder that is already on disk. Sixteen rules in six groups (text, injection, exec, perm, net, intent), a fixed report template, and one of three verdicts from a published table: INSTALL, INSTALL WITH EDITS, REJECT.
- Uses only Read, Grep and Glob. No hooks, no `bin/`, no MCP, nothing to install or run.
- Four fixtures with golden expectations in `examples/`, a maintainer-run `node --test` structure check with no packages, and goldens for the four sibling plugins and for itself.
- Name search on 2026-11-22: one web search and two GitHub repository searches for "gatehouse" with Claude skill or plugin terms found nothing by that name. Not exhaustive; repeat before release.
- Changes this cycle, same version: Step 0 checks the path before refusing `owner/repo`-shaped input; the `hidden-text` fixture is committed with its tag characters as escapes and `examples/make-fixtures.mjs` writes the real ones into a temporary copy, so the plugin folder no longer rejects itself (prediction in `expected/self.md` is now INSTALL WITH EDITS); sweeps run in count mode with a 20-hit judging cap and quieter S-HIDDEN, S-HOOK and S-EGRESS recipes; a Per plugin table for marketplaces; an audit receipt and an optional diff mode against a previous report; scripts wired to hooks are read (S-DESTRUCT); new recipes S-DEP-SPEC and S-CI; "(coverage incomplete)" suffix instead of a fourth verdict; notes on saving and on remote sources.
- Not yet measured: no model-run audit has been recorded. See `examples/results/`. The reference-token figure (about 10k) is an estimate. `/gatehouse` versus `/gatehouse:gatehouse` and `plugin details` have not been observed live.
