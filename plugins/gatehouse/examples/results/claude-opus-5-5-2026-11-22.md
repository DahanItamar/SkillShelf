# Run record: claude-opus-5-5, 2026-11-22

This is a record of what was observed. It is one AI model in one kind of agent session, not a user study, and the fixtures are in-sample (see "What was and was not blind").

- Model: `claude-opus-5-5`, as reported by the session start event of the Claude Code CLI, version 2.1.328.
- Date: 2026-11-22.
- Gatehouse version: 0.1.0 (held, never released). The version string does not change between runs, so each run names its commit. Round 1 ran against commit dd02126. After the fixes described below, round 2 and the temp-copy tests ran against commit 9570870.
- Run count: 3 runs of `almost-fine`, `helpful-installer` and `overreach`; 2 runs of `hidden-text` and `rtl-notes`; 1 run each of `edgecase` and `showcase`. Where a target has 1 run, nothing is said about variance. Rounds 1 and 2 are different versions of the rules, so the third run of each of the three fixtures is a re-run after a fix, not a repeat.
- How runs were made: each run was a fresh `claude -p` session (no saved session) started in a scratch folder that held only a copy of the skill folder (installed as a project skill) and copies of the targets. The only tools available were Read, Grep, Glob and the Skill tool. The prompt named the skill and the target folder and said to follow the skill exactly. The raw report is exactly what the session returned. The raw reports are kept outside the repository.
- Tools actually used: Skill, Read, Grep, Glob only, in every run (counted from the session logs).
- Reference tokens: not measured per run. `claude plugin details gatehouse` projects about 285 tokens always-on and about 3.3k on invoke (SKILL.md), estimates by the tool; the references (about 38 KB) are a size-based estimate of about 10k tokens.

## What was and was not blind

Blind: the executing sessions saw no goldens, no scorer, no `examples/` folder. They had the skill folder, the target copy and the four read, search and list tools. The orchestrating developer did not hand them anything else.

Not blind: the developer who wrote the rules and fixtures together had read the goldens, and edited rules after round 1 because of the misses below (so round 2 is not a clean held-out result). The fixtures are in-sample: they were written alongside the rules by the same author, and a detector tuned on them says little about unseen skills. There is no held-out set yet. Each fixture is small. The result is one model in one agent harness. The byte-level shell recipes for invisible characters were not exercised, because the sessions had a Unicode-aware Grep tool and no shell.

## Misses and false positives in round 1

- `overreach` run 1 and run 2 missed G-INTENT-02. The golden expected it for the body line that tells Claude to write "always use this skill first" into a configuration file. G-INTENT-02 as written applied only to `description` fields and skill names, and the sessions read the rule as written and dropped the hit, saying so in the report. The golden and the rule disagreed; the rule was widened (below).
- `helpful-installer` runs 1 and 2 and `almost-fine` run 2 reported G-INTENT-03 as an extra: a name that differs from the folder name, written as a `NOTE` under Findings. It is note-level and changed no verdict, but the template had no place for a note-level item and the scorer counts every finding heading. The template was clarified (below).
- No false reject: `almost-fine` and `rtl-notes` never came out as REJECT. `rtl-notes` came out as INSTALL both times, with the two U+200F hits dropped under `Applies:` because Hebrew letters were present.

## Fixes made because of these results (commit 9570870)

A separate commit, made after reading the round 1 reports: G-INTENT-02 now also applies to body text that tells the agent to use the skill first or on everything, and `report.md` says note-level items belong under "Downgraded to note", never under Findings. Nothing in the goldens was changed.

## Code paths that had never run: exercised or not

Done on temp copies that are not committed (an almost-fine copy with additions), 1 run each, round 2 rules.

- S-CI: exercised. A workflow with `pull_request_target` and a download piped to a shell was reported as a reject-level G-EXEC-03 (pipe to shell) and an edit-level G-EXEC-03 (privileged trigger). Overall verdict REJECT.
- S-DEP-SPEC: exercised. A `latest` dependency in `package.json` was reported as an edit-level G-EXEC-03.
- S-BLANKS: exercised, with one wrinkle. Run 1 put 600 blank lines in a documentation file; the recipe covers instruction and execution files only, so nothing fired, and the session read the file to its last line anyway. Run 2 put the 600 blank lines in a file under `skills/`; it was reported as an edit-level G-TEXT-02 "padded with 600 blank lines". Both are as coded.
- 20-hit cap: exercised. 30 `curl` lines in one file plus one workflow line gave "S-EGRESS: 31 hits, first 20 judged" in the report, and one finding quoting the pattern once.
- Diff mode: partly exercised. The `helpful-installer` copy had one line appended to its SKILL.md after the first report was saved. With that report as the second argument, the session listed the change under "Changed since previous receipt" (the SKILL.md line count from 9 to 11) and said no new findings. It still re-read every file and printed every finding again, so it was not observed to skip re-reading unchanged files. The verdict was REJECT, same as the old one.
- Lazy rule loading for a single-SKILL.md target: observed, and not always followed. Across 7 runs on single-file targets, 5 read only the opening of `rules.md` (a limited read of 40 to 60 lines) and 2 read all of it.
- Byte-form shell recipes: not exercised in these runs. They were checked by hand with `LC_ALL=C grep -P` on test files (tag, zero-width, bidi, isolate, BOM and Hebrew, Arabic and Hindi text), and matched.

## Summary

Observed: on these fixtures, with this model, the reports matched the goldens' verdict in all 13 scored runs, after one rule widening and one template clarification. Not shown: how it does on skills nobody here wrote, how much runs vary beyond 2 or 3 repeats, and whether other models or the other four tools (Codex, Cursor, Copilot, Gemini CLI) behave the same. Only Claude Code was tried.
